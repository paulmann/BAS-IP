# 02 · Быстрый старт

[← Home](Home.md)

Сценарий «от чистой машины до открытого шлагбаума» за 10 минут. Предполагается,
что приложение установлено ([01 · Установка](01-Installation.md)) и вы вошли
под администратором.

## 1. Проверьте здоровье системы

**Админка → Система** или консоль:

```bash
php bin/bas-ip doctor
```

Зелёные галочки: PHP, БД, права на `storage/`, ключ приложения, HTTPS.
Предупреждения подскажут, что донастроить (2FA сотрудников, боевой драйвер
устройства вместо эмулятора и т.п.).

## 2. Подключите шлагбаум

**Админка → Шлагбаум → Устройства → Добавить**:

| Поле | Что указать |
|---|---|
| Драйвер | `BAS-IP Camdroid (/api/v0)` для панелей BAS-IP; `HTTP-реле` для сторонних контроллеров; `Эмулятор` чтобы попробовать без железа |
| Base URL | `http://192.168.1.20/api/v0/` (адрес панели в локальной сети) |
| Логин/пароль | учётка администратора панели |
| Канал реле | номер канала замка (обычно 1) |

Кнопка **«Проверить»** на карточке устройства покажет статус SIP, версию
прошивки и сделает тестовое открытие. Подробности — [11 · Устройства](11-Devices.md).

## 3. Заполните базу жителей

Варианты:

* **Импорт** (быстро для дома): **Админка → Данные → Импорт** — загрузите
  CSV/JSON/Excel (кнопка «Скачать образец» даст шаблон). Мастер покажет
  предпросмотр и маппинг колонок, затем импортирует. Дубли определяются по
  квартире/ФИО (настраивается).
* **Вручную**: **Админка → Жители → Добавить**. В карточке: ФИО, квартира,
  несколько телефонов и e-mail, машины (госномер + марка), площадь, число
  жителей, чекбоксы **«доступ»**, **«включен»**, «участвует в оплатах».

> Правило системы: **все расчёты и массовые действия учитывают только
> активных (включённых) жителей**. Список по умолчанию показывает именно их.

Каждому жителю можно создать учётную запись кабинета: карточка жителя →
**«Создать учётную запись»** (логин = квартира или e-mail, временный пароль
придёт/показывается один раз, при первом входе — смена).

## 4. Откройте шлагбаум

* **Панель оператора** (`/panel`, доступна admin и operator): большая кнопка
  «Открыть», статус устройства, снимок камеры, последние события.
* **Из карточки жителя**: кнопка «Открыть» — откроет и запишет событие
  на квартиру.
* **Из кабинета жителя**: житель заходит под своей учёткой → кнопка
  «Открыть шлагбаум».

Каждое открытие пишется в **Админка → Шлагбаум → Журнал**: кто, когда,
тип доступа (свой/гостевой/API/ручной), квартира, результат, устройство.

## 5. Выпустите гостевой пропуск

Житель (в кабинете) или администратор (**Админка → Гостевой доступ → Создать**):

1. Выберите жителя/квартиру, срок (по умолчанию **12 часов**), имя гостя,
   (опционально) госномер.
2. Система выдаст: **ссылку с QR-кодом** (отправьте гостю в мессенджер),
   **короткий код** `7K4M-Q2XD` и **PIN** для клавиатуры панели.
3. Гость открывает ссылку на телефоне → кнопка «Открыть шлагбаум».
   Без регистрации и без вашего участия. Каждое использование логируется.

Лимиты, сроки и уведомления настраиваются в **Админка → Настройки → Гостевой доступ**.

## 6. Начислите оплату за месяц

**Админка → Оплаты → Мастер начисления**:

1. **Сумма**: например `15 000` ₽ — общая сумма обслуживания за период.
2. Система покажет: активных участников (например, 20), сумму на каждого
   (750 ₽), способ распределения (поровну / по площади / по жителям / по доле).
3. **Период**: «Октябрь 2026», срок оплаты (например, 14 дней), ссылка на
   оплату (CloudTips/ЮKassa/Сбербанк-ссылка — с подстановками `{sum}`, `{id}`…).
4. **Сообщение**: можно написать своё или оставить автогенерируемое —
   «Здравствуйте, {name}! Начислена оплата за {period}: {amount}…».
5. **«Выставить счета»** → счета созданы, уведомления встали в очередь,
   жители получили письма/сообщения со ссылкой.

Дальше: оплаты принимаете в **Оплаты → Платежи** (наличные/перевод/онлайн),
или они приходят по API из платёжного сервиса. Должники видны на
**Оплаты → Должники**, кнопка «Напомнить» рассылает напоминания.
Перерасчёт при изменении суммы/состава — [08 · Биллинг](08-Billing.md).

## 7. Настройте уведомления

**Админка → Настройки → Уведомления**: включите каналы (SMTP, Telegram-бот,
SMS-шлюз, webhook) и укажите, что куда отправлять. Тестовая кнопка «Отправить
проверочное» — сразу покажет результат. Без настроенных каналов всё пишется
в журнал (`log`) — ничего не потеряется. Подробности — [09 · Уведомления](09-Notifications.md).

## 8. Закройте периметр

Чек-лист production-установки:

* [ ] HTTPS работает, `app.url` указан с `https://`;
* [ ] `app.env=production`, `app.debug=false`;
* [ ] у всех сотрудников включена **2FA** (Профиль → Безопасность);
* [ ] пароль администратора сменён на уникальный;
* [ ] `php bin/bas-ip doctor` — 0 ошибок;
* [ ] cron `schedule:run` добавлен;
* [ ] автобэкап включён (**Настройки → Бэкапы**) или cron `backup:create`;
* [ ] демо-данные удалены (если засевали): **Админка → Данные**;
* [ ] API-токены созданы только для нужных интеграций, с минимальными областями.
